# Как доделать КТ2

## Что уже готово

- `инструкции/` — три финальные инструкции A, B, C (сдаются как есть). **После прогона их не менять**: кэш ответов привязан к хэшу текста, правка = все ответы этой версии запросятся заново.
- `КТ2_анализ.ipynb` (+ версия для Colab) — весь эксперимент: прогон моделей, журнал, таблицы, графики, режим работы, экономия времени. Проверен целиком на тестовых данных.
- `rust/` — guard, оценка по эталону, бутстрэп, симуляция смен (`cargo test` — 16 тестов).
- `data/llm_raw.jsonl` — 6 ответов версии A (INC-001…006) с пробного прогона на CPU. Новые ответы допишутся к ним. Если хотите все ответы с одной машины — удалите файл.

## Что осталось

1. Прогнать модели: 30 × 3 на `qwen2.5:7b` и 30 × 3 на `llama3`.
2. Вручную проверить ответы A.
3. Дописать тексты по результатам, README и записку.

## Шаги

1. Забрать ветку: `git fetch && git switch kt2`.
2. Модели: поставить Ollama, затем `ollama pull qwen2.5:7b` и `ollama pull llama3`. Ollama сама использует видеокарту, весь прогон займет минуты.
3. Rust: `cd КТ2_AI_диспетчер_инцидентов/rust && cargo build --release`. Если не собрать заранее, ноутбук попробует собрать сам (нужен `cargo`).
4. Python: `pip install pandas matplotlib requests jupyter`.
5. Открыть `КТ2_анализ.ipynb` **из папки КТ2** и выполнить все ячейки. Ячейка с моделью спрашивает только недостающие ответы и пишет их в `data/llm_raw.jsonl`, ее можно прерывать и запускать снова.
6. Ручная проверка. Открыть `КТ2_ответы_модели.md` (все ответы как есть) и `КТ2_журнал_результатов.csv`. У A поля вытаскиваются из свободного текста правилами. Где правило ошиблось, добавить строку в `data/ручная_проверка.csv` (в reason без запятых) и перезапустить ноутбук, ответы возьмутся из кэша:

   ```
   incident_id,prompt_version,model,field,value,reason
   INC-005,A_короткая,qwen2.5:7b,error_source,выдумка,придумала транзакции и счет клиента
   INC-004,A_короткая,qwen2.5:7b,model_owner,,разработчики упомянуты только для отчета
   ```

   Какие поля можно править:
   - `model_severity`, `model_owner`, `model_first_action`, `evidence_quote`, `unknowns`, `model_human_review` — что вытащено из ответа;
   - `owner_ok`, `first_action_ok` — `да` / `частично` / `нет`; `evidence_ok` — `да` / `пересказ` / `выдумка` / `нет`;
   - `error_source` — **полный** список источников через `;` (неоднозначность, потеря факта, выдумка, неверная срочность, чрезмерная автоматизация);
   - `dangerous_error` со значением `нет` снимает опасную ошибку; `comment` заменяет комментарий.
7. Дописать:
   - в ноутбуке все блоки «Дописать после прогона» (результаты, стабильность, пять ошибок, guard, экономия, вторая модель, решение);
   - раздел «Вывод» в `README.md`;
   - записку `КТ2_записка.md` или в Word, 1–2 страницы: пять опасных ошибок, безопасный процесс (можно взять из «Шаг 6» ноутбука), расчет экономии.
8. Сдать: `КТ2_журнал_результатов.csv`, папку `инструкции/`, записку. Залить: `git add -A && git commit -m "КТ2" && git push`, потом влить `kt2` в `main`.

## Если что-то не так

- «Ollama не отвечает» — запустить приложение Ollama или `ollama serve`.
- На Windows бинарник называется `kt2-incident-guard.exe`, ноутбук это учитывает.
- Ответы на видеокарте могут немного отличаться от CPU даже при том же seed. Это нормально, но для чистоты эксперимента можно удалить `data/llm_raw.jsonl` и прогнать все заново.
- Rust отдельно, из папки КТ2: `rust/target/release/kt2-incident-guard --data data --model qwen2.5:7b`.
