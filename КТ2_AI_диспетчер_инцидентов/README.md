# КТ2 — AI-диспетчер критических инцидентов

## Вывод

Система работает так: language-модель читает сообщение об инциденте и готовит карточку (критичность, владелец, первый шаг, цитата-доказательство, что неизвестно, нужен ли человек), а после нее стоит guard — простые правила на Rust, которые решают, можно ли пустить карточку дальше без человека. Сравнивал три версии инструкции на 30 обязательных случаях, модель qwen2.5:7b локально через Ollama, для проверки те же запросы в llama3.

| версия | приоритет | владелец | первый шаг | цитата дословно | неизвестное | эскалация где нужна | опасных ошибок |
|---|---|---|---|---|---|---|---|
| A — короткая | 43% | 7% | 10% | 10% | 23% | 3 из 7 | 17 из 30 |
| B — структура | 47% | 37% | 7% | 97% | 100% | 7 из 7 | 14 из 30 |
| C — управляемый AI | 83% | 77% | 37% | 97% | 100% | 7 из 7 | 3 из 30 |

Одна структура (B) дает формат, цитату и неизвестное, но не правильный приоритет и владельца, а человека зовет почти всегда (28 из 30). Работает только полный набор C: правила критичности, справочник владельцев, правило «отрасль — это канал», запрет на выдумывание и примеры. На llama3 то же самое: у C 3 опасные ошибки против 15 у A и 24 у B. Разница C и A по опасным ошибкам −47 п.п. [−71; −24], но 30 случаев — это всего 9 разных текстов, так что интервалы широкие.

Guard не пропустил в «авто» ни одной опасной ошибки. Все три ошибки C одного типа: сервис перестал отвечать после обновления, резерв работает, клиенты затронуты, а модель ставит Высокий вместо Критического. Они уходят диспетчеру на подтверждение. Экономия по симуляции — 102–205 минут за смену (153–307 часов в месяц при работе 24/7), а главное — критический инцидент не ждет в очереди: P90 до первого действия 7–10 минут против 15–86 минут вручную.

Решение: **revise**. До пилота надо:
1. добавить в C пример «основной сервис не отвечает, резерв работает → Критический» и правило в guard на такие сообщения;
2. добавить в C пример про склад (все пять сообщений про терминалы ушли в «авто» не тому владельцу) и проверку в guard, что владелец есть в справочнике;
3. проверить на новых, неповторяющихся сообщениях;
4. запустить пилот на 2–4 недели в режиме «AI предлагает, человек подтверждает», «авто» только для Низкий/Средний после недели без ошибок. Контроль: опасных ошибок в «авто» 0, время до первого действия по критическим, реальные замеры времени диспетчера.

## Что сдается

| пункт задания | файл |
|---|---|
| 1. Журнал 30 × 3 | `КТ2_журнал_результатов.csv` (все ответы целиком — `КТ2_ответы_модели.md`) |
| 2. Три финальные инструкции | `инструкции/A_короткая.txt`, `инструкции/B_структура.txt`, `инструкции/C_управляемый_AI.txt` |
| 3. Записка на 1–2 страницы | `КТ2_записка.md` (то же в Word: `КТ2_записка.docx`) |

## Что где лежит

| файл | что это |
|---|---|
| КТ2_анализ.ipynb | весь эксперимент на Python: прогон модели, журнал, таблицы, графики, разбор ошибок, режим работы |
| КТ2_анализ_colab.ipynb | то же для Colab: без Ollama и Rust, на сохраненных результатах |
| rust/ | guard, оценка по эталону, бутстрэп и симуляция смен диспетчера |
| data/ | исходные сообщения, ответы модели `llm_raw.jsonl`, рубрика, ручная проверка, допущения по времени, результаты Rust |
| img/ | графики |
| КТ2_задание.pdf | задание |

Ноутбук и Rust работают вместе, как в КТ1: ноутбук спрашивает модель и копит ответы в `data/llm_raw.jsonl`, Rust их разбирает, прогоняет через guard, оценивает по эталону, считает доверительные интервалы и симуляцию смен, а ноутбук забирает CSV и строит выводы.

## Как запустить

1. Модель: поставить [Ollama](https://ollama.com), потом `ollama pull qwen2.5:7b` и `ollama pull llama3` (вторая нужна только для проверки на другой модели).
2. Rust: `cd rust && cargo build --release`, тесты — `cargo test`.
3. Ноутбук: pandas, matplotlib, requests, запустить все ячейки сверху вниз. Ответы, которые уже лежат в `data/llm_raw.jsonl`, второй раз у модели не спрашиваются, поэтому без Ollama ноутбук тоже отрабатывает целиком. Полный прогон с нуля на видеокарте (у меня RTX 5080) — минут 11, на CPU — часов пять.
4. Только Rust, из папки КТ2: `rust/target/release/kt2-incident-guard --data data --model qwen2.5:7b`.
